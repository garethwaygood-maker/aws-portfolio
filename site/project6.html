OVERVIEW

Project objective

The objective was to approach an existing AWS account from a security-engineering perspective rather than simply deploy new infrastructure. The assessment focused on four complementary areas: API audit history, configuration compliance, threat detection and workload vulnerability coverage.

The exercise used AWS-native security services to identify security posture issues, investigate findings and determine practical remediation priorities.

AUDIT & FORENSICS

CloudTrail

A multi-Region CloudTrail trail was configured to provide an auditable history of AWS management activity. Trail logs were delivered to Amazon S3 and protected using AWS KMS encryption, with log-file validation enabled.

This provides the forensic layer of the assessment: who performed an action, what API call was made, when it occurred and where the request originated.

  • Multi-Region trail enabled.
  • Management events recorded.
  • Central S3 log storage.
  • SSE-KMS encryption enabled.
  • Log-file validation enabled.
CONFIGURATION COMPLIANCE

AWS Config

AWS Config was enabled with continuous recording to establish visibility of resource configuration and configuration history. Managed Config Rules were used to evaluate selected security controls.

The initial controls were s3-bucket-public-read-prohibited and restricted-ssh. The assessment identified four S3 resources as non-compliant with the public-read control. Rather than treating every alert as an automatic remediation, the finding highlighted the need for business context: some buckets supported deliberately public static websites, while private CloudFront-backed workloads should use private S3 access.

This separates detection from remediation and avoids security changes that could unnecessarily break a legitimate workload.

THREAT DETECTION

Amazon GuardDuty

Amazon GuardDuty was enabled to add continuous intelligent threat detection across the AWS account. Sample findings were generated so the triage workflow could be explored without deliberately compromising a live resource.

The generated findings included critical attack sequences representing potential IAM credential compromise. The investigation view correlated multiple signals and mapped activity to MITRE ATT&CK tactics including persistence, privilege escalation and defence evasion.

This demonstrates the distinction between services: CloudTrail records activity, while GuardDuty analyses telemetry to identify behaviour that may represent a security threat.

VULNERABILITY MANAGEMENT

Amazon Inspector

Amazon Inspector was activated to assess vulnerability-management coverage across EC2, ECR and Lambda resources. Account coverage showed scanning capabilities enabled, but the EC2 resource review exposed an important operational issue.

Four EC2 instances were discovered. After starting representative web and application instances, Inspector continued to report them as Unmanaged EC2 instance rather than actively scanning them.

This is itself a meaningful security finding: enabling a security service does not guarantee that workloads are covered. The recommended remediation is to validate Systems Manager management, IAM instance-profile permissions, SSM Agent health and network connectivity to required AWS service endpoints, then confirm Inspector scanning coverage.

FINDINGS & REMEDIATION

Security findings

01 · CONFIG

Public S3 access detected

Four buckets were identified as non-compliant with the public-read rule. Remediation must distinguish deliberately public static-site hosting from workloads that should use private S3 access through CloudFront OAC.

02 · INSPECTOR

EC2 coverage gap

Running EC2 workloads remained unmanaged by Inspector. Recommended remediation is to verify SSM registration, IAM permissions, SSM Agent operation and network paths before validating vulnerability scanning.

03 · LOGGING

Audit trail established

CloudTrail provides encrypted, validated management-event history in S3, creating an audit and investigation foundation for future security incidents.

04 · DETECTION

Threat-detection workflow validated

GuardDuty sample findings were used to practise severity-based triage and investigation of correlated attack signals without introducing a real compromise.

SECURITY ENGINEERING

Key lessons

  • CloudTrail answers who did what and when.
  • AWS Config records resource configuration and evaluates compliance.
  • GuardDuty analyses telemetry to identify suspicious behaviour and threats.
  • Inspector assesses workload vulnerability exposure, but coverage must be verified rather than assumed.
  • Security findings require business and architectural context before remediation.
  • Effective cloud security combines visibility, detection, investigation, remediation and continuous verification.
OUTCOME

Project outcome

The project established a practical AWS-native security assessment workflow across audit logging, configuration compliance, threat detection and vulnerability management. It produced real posture findings rather than simply enabling services: public S3 configuration was identified through Config and an EC2 vulnerability-scanning coverage gap was identified through Inspector.

The resulting workflow provides a foundation for a broader security programme incorporating Security Hub, IAM and Identity Center review, AWS Organizations and SCP governance, KMS and Secrets Manager controls, Systems Manager patching, WAF and CIS / AWS Well-Architected Security Pillar assessment.
