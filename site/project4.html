Project 04

Highly Available Infrastructure with Terraform

AWS Infrastructure as Code using Terraform, GitHub and GitHub Actions.

In Progress — Network Foundation Deployed

Project Overview

This project demonstrates how a production-style AWS environment can be designed and deployed using Infrastructure as Code rather than manually creating each resource through the AWS Management Console.

Terraform is used to define the AWS infrastructure in code, GitHub is used for source control, and GitHub Actions will be used to automate Terraform validation as the project develops.

Current Architecture

  • VPC: 10.40.0.0/16
  • Two Availability Zones: eu-west-2a and eu-west-2b
  • Public subnets: 10.40.1.0/24 and 10.40.2.0/24
  • Private subnets: 10.40.11.0/24 and 10.40.12.0/24
  • Internet Gateway attached to the VPC
  • Public route table with 0.0.0.0/0 routed to the Internet Gateway
  • Separate private route table
  • Route table associations for all four subnets
  • Security Groups, EC2 and load balancing to follow

Terraform Project Structure

Deployment Workflow

Write Terraform code → terraform init → terraform fmt → terraform validate → terraform plan → terraform apply → verify the infrastructure in AWS → commit and push the code to GitHub.

The project is being built incrementally so that each resource can be understood, planned, deployed and tested before moving to the next part of the architecture.

Current Build Stage

The core network foundation is now deployed with Terraform: a VPC, four subnets across two Availability Zones, an Internet Gateway, separate public and private route tables, the public Internet route and all subnet route table associations. A final terraform plan returned No changes, confirming that AWS matches the configuration. The Terraform code is also version controlled with Git and published to a public GitHub repository. Security Groups are the next build stage.
