Project 04

Highly Available Infrastructure with Terraform

AWS Infrastructure as Code using Terraform, GitHub and GitHub Actions.

In Progress

Project Overview

This project demonstrates how a production-style AWS environment can be designed and deployed using Infrastructure as Code rather than manually creating each resource through the AWS Management Console.

Terraform is used to define the AWS infrastructure in code, GitHub is used for source control, and GitHub Actions will be used to automate Terraform validation as the project develops.

Planned Architecture

  • Amazon VPC
  • Two Availability Zones
  • Public subnets
  • Private subnets
  • Internet Gateway
  • Route tables and routing
  • Security Groups
  • Application Load Balancer
  • Amazon EC2 web servers
  • NAT Gateway where required
  • Terraform outputs for useful deployment information

Terraform Project Structure

The infrastructure will be separated into clear Terraform configuration files so the project remains easy to understand, maintain and extend. 

aws-project-04-terraform/
├── main.tf
├── variables.tf
├── outputs.tf
├── providers.tf
├── terraform.tfvars
├── .gitignore
└── README.md

Deployment Workflow

Write Terraform code → terraform init → terraform fmt → terraform validate → terraform plan → terraform apply → verify the infrastructure in AWS → commit and push the code to GitHub.

The project is being built incrementally so that each resource can be understood, planned, deployed and tested before moving to the next part of the architecture.

Current Build Stage

The initial stage is to create the Terraform repository and file structure, configure the AWS provider, and deploy the VPC. Public and private subnets, routing, security, load balancing and EC2 resources will then be added in logical stages.

Skills Demonstrated

  • Terraform Infrastructure as Code
  • AWS VPC networking
  • Multi-AZ architecture
  • Public and private subnet design
  • AWS load balancing and EC2
  • Infrastructure source control with GitHub
  • Terraform validation with GitHub Actions
  • Repeatable and version-controlled cloud deployment
